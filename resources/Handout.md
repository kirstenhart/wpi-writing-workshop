
# Clear Communication in Code
## API & UI Workflow Documentation

Presented by: Kirsten Hart, Technical Writer @ MathWorks

## Elements of Good Documentation
- **Clarity:** Use simple, precise language.
- **Conciseness:** Use shorter sentences and get to the point quickly.
- **Consistency:** Use consistent terms, formatting, and tone throughout.
- **Structure:** Organize content logically with headings, lists, and examples. A well-structured document is “scannable” — readers can find what they need quickly.
- **Examples and Visuals:** Include sample code, diagrams, and screenshots.
- **Audience Awareness:** Write for your audience’s level of expertise. Provide appropriate depth of explanation. *For example, documentation for end-users will read differently (more high-level, less assumed knowledge) than documentation for experienced developers.*
- **Active Voice:** Prefer active voice in technical documentation. *For example, say “The system returns the transaction ID” instead of “The transaction ID is returned”.*
## API Documentation
- **Consistency in format and naming:** Consistent naming conventions improves readability for the user.
- **Error handling and codes:** Document possible error responses or codes. Explain what each error means and how the user should handle it.
- **Show examples:** Help users understand API usage through simple examples.
## UI Workflow Documentation
- **Clear labels and terminology:** Use the same terms in documentation that appear on the UI.
- **Visual aids:** Include screenshots or sketches of the UI when possible, with callouts or captions to show where to click and what happens.
- **Show navigation paths:** Document how a user gets from one screen or state to another (e.g., *After logging in, the user is taken to the Dashboard screen, where they can see account information*).
